# meditor 製品要件定義書（レビュー案）

## 目的と利用者

meditor は、AI がゲーム実況の動画を編集する Windows 専用のデスクトップアプリ。制作者は実況動画、ゲーム音、複数話者の音声を取り込み、AI に編集作業を任せる。AI が行った編集はタイムラインや字幕に反映され、制作者は GUI で結果を確認し、必要に応じて手作業で編集して、公開用の動画と字幕を書き出せる。

製品の対応 OS は Windows のみ。C++20・wxWidgets のアプリから、再生・プロキシ生成・動画書き出しに FFmpeg を利用する。実行時の依存構成は Qt、QML、Qt Multimedia、Python を含まない。GUI では、字幕10,000件での応答性と、連続スクラブ時の映像追従を重視する。

## 基本の利用フロー

1. 制作者が実況動画、ゲーム音、話者音声をプロジェクトに取り込む。
2. 自動文字起こしで日本語の発話と時刻を取得する。話者トラックを指定した場合は、その情報を字幕に反映する。
3. AI に編集を依頼する。AI は素材と文字起こし結果を使い、指定された作業を実行して編集結果をプロジェクトに反映する。
4. 制作者は GUI で編集結果をプレビューし、字幕やタイムラインを修正できる。同じ GUI から手作業で直接編集することもできる。
5. 編集結果を保存し、動画と字幕を書き出す。

## 初回リリースまでの範囲

初回リリースの必須機能は、AI による動画編集、GUI による手動編集、自動文字起こし。AI に任せる具体的な編集操作や対応素材の範囲はレビューで決める。最初の評価素材は実況動画1本、ゲーム音1本、話者音声2本以上、字幕10,000件を想定する。

| 項目 | 現行 | 初回リリース要件（案） |
| --- | --- | --- |
| AI 動画編集 | 未実装 | AI が編集指示を受けて動画を編集し、編集結果をタイムラインに反映する。基本の自動編集操作の候補は、指定区間の切り出しと不要区間のカット |
| 素材の取り込み | 動画1本、ステレオ48 kHz PCM WAV、UTF-8 SRT | 動画内の音声ストリームと外部音声を選んで取り込める。各音声をゲーム音または話者に割り当てられる。対応入力形式は下記の決定事項で確定する |
| プロジェクト | バージョン付き UTF-8 JSON、相対メディアパス | 再オープンで素材、字幕、話者、編集区間、音量・オフセットを復元する。素材が見つからない場合は場所を指定し直せる |
| 字幕編集 | 仮想化一覧で本文と話者を編集、開始時刻へ移動 | 本文・話者・開始と終了の編集、字幕の追加・削除、編集操作の取り消しとやり直し。日本語 IME の変換中も別の行を書き換えない |
| タイムライン編集 | シークとプレビュー | 元動画の必要区間を分割・トリムできる。編集に伴う動画、音声、字幕の時刻移動がプレビューと書き出しで一致する |
| プレビュー | FFmpeg の CPU デコード、連続シーク、手動指定の短 GOP プロキシ | ドラッグ中は最新のシークを優先し、手を離した位置から元動画と音声を同期して再開する。プロキシの生成、再利用、失効をアプリが管理する |
| 音声 | WAV トラックをオフセット・ゲイン付きでミックス | トラックごとの音量とミュートを UI で変更できる。変更がプレビューと動画書き出しに反映される |
| 日本語の自動文字起こし・時刻合わせ | SRT の取り込み | 取り込んだ音声から日本語の発話と単語時刻を自動生成し、プロジェクト時刻に配置する。結果は AI 動画編集で利用でき、利用者も GUI で修正できる |
| 書き出し | 未実装 | 字幕を UTF-8 SRT で出力する。編集済み映像とミックス音声を MP4 で出力する。焼き込み字幕を初回に含めるかは要決定 |
| Windows 配布 | CI のビルド、テスト、画面撮影 | クリーンな対応 Windows 環境で配布物を起動し、取り込みから書き出しまで再現できる。付属ランタイムとライセンスを確認する |

画面合成やエフェクト、複数動画の合成、単一音声の自動話者分離、共同編集は初回リリース後に検討する。

## AI 編集・手動編集・保存の受入条件

| Given | When | Then |
| --- | --- | --- |
| 取り込み済みの実況動画と文字起こし結果がある | 初回対応範囲の動画編集を AI に依頼する | AI の編集結果をタイムラインでプレビューでき、実行した編集を確認・取り消しできる |
| AI が編集したプロジェクトを開いている | GUI で字幕やカット位置を手作業で変更して保存する | 手作業で変更した内容が、再オープン、プレビュー、書き出しに反映される |
| 保存済みの編集内容がある | AI の編集処理を中断するか処理に失敗する | 処理前の編集内容を保持し、GUI から作業を続けられる |
| 動画、ゲーム音、話者音声2本、字幕10,000件がある | プロジェクトを開き、一覧の先頭・中間・末尾の字幕を日本語 IME で編集して再オープンする | 編集した行の本文・話者・時刻が保存される。その他の字幕、音声設定、素材参照を保持する |
| ゲーム音と話者音声に異なるオフセットを設定したプロジェクトがある | 区間を分割・トリムし、取り消してからやり直す | 各操作に対してプレビューの映像と音声、字幕の表示時刻が対応する。履歴をたどると同じ編集状態に戻る |
| 元動画を再生中で、有効なプロキシがある | 往復して連続スクラブし、別の時刻で手を離す | 上書きされたシークの映像や音声が後から再生されず、最後の位置から元動画とミックス音声で再開する |
| 元動画の更新、プロキシ欠落、対応しないハードウェアのいずれかがある | プレビューまたはスクラブを行う | 有効な元動画の経路へ切り替え、状態を表示する。素材が欠落していれば、再指定までプロジェクト内の編集内容を保持する |
| オフセット付きの話者トラックを登録している | 日本語文字起こしを実行して字幕を修正する | 話者と単語時刻をプロジェクト時刻へ反映し、本文・時刻の修正を保存できる。中断・失敗時に既存字幕を保持する |
| 分割・トリム済みの区間と音量設定がある | 字幕と動画を書き出し、対応プレーヤーで開く | 先頭・末尾とカット境界で編集後の時刻が一致する。字幕、音声トラックの反映、動画・音声の長さを検証できる |

保存中のエラーや中断のあとも、直前の正常なプロジェクトを開けること。素材は参照して使い、編集操作で元ファイルを書き換えない。

## Windows の性能と計測

比較は同じ Windows PC、素材、表示設定、音声出力、操作列で行う。字幕10,000件とゲーム音・話者音声2本以上を読み込み、同じ操作を元動画と短 GOP プロキシで各3回以上実行する。CI の合成素材はビルドと機能回帰の確認に使う。製品の性能判定では、基準 PC と代表的な実況素材を固定し、スクラブに使う区間、入力形式、GOP、解像度、フレームレートを記録する。

| 指標 | 測り方 | 初回目標（提案値） |
| --- | --- | --- |
| シーク入力からフレーム表示 | 入力イベントから、その要求に対応する映像が画面に提示されるまで。元動画・プロキシを別集計 | 元動画 p95 150 ms 以下、プロキシ p95 80 ms 以下 |
| 再生再開時の A/V ずれ | 映像提示と音声ループバックを共通の時間軸で照合し、差の絶対値を計測 | p95 50 ms 以下 |
| 字幕10,000件での編集応答 | 一覧選択、本文入力の確定、話者変更から画面への反映まで。先頭・中間・末尾で計測 | 各操作 p95 50 ms 以下 |
| プレイヘッド追従 | 連続再生とシーク再開中に、描画されたプレイヘッドと提示映像のプロジェクト時刻の差を計測 | p95 を記録し、基準測定後に上限を決める |
| UI 停止 | スクラブと字幕編集時のイベントループの遅延 | 通常操作中の 100 ms 超の停止を記録し、再現条件を確認する |

表示レイテンシーには、最後まで有効な要求の未表示件数と、後続入力で上書きされた件数を併記する。表示できた要求の p95 と一緒に確認する。既存の描画・音声キューの時刻は原因分析に使い、実表示と物理音声の同期は実機で判定する。数値は基準 PC と初回実測を踏まえて確定する。 [計測手順と現状](performance.md)

Windows 高速経路は FFmpeg の D3D11VA デコード、Direct3D 11 描画、WASAPI の音声出力と再生時計を第一候補とする。対応する素材と GPU では、デコードから描画までの CPU 読み戻しの有無を記録する。非対応時に CPU 経路で編集を続けられることを受入条件にする。共通のタイムライン時刻とシーク制御を OS 固有の再生機構から分離する。 [設計](design.md)

## 作業順と完了判定

1. **自動文字起こしと AI 編集の縦断試作**。代表素材で音声の取り込みから日本語文字起こし、AI による基本的なカット編集、GUI での確認・修正までつなぐ。Windows 実機のプレビュー基準も測る。
2. **編集操作と高速プレビュー**。AI と GUI から使う字幕・カット編集と履歴を整える。プロキシ管理と Windows のネイティブ再生経路を段階的に実装し、基準測定と比較する。
3. **書き出しと Windows 配布**。AI と人が編集した結果を字幕・動画に書き出し、クリーンな Windows 環境で取り込みから書き出しまで検証する。

通常の PR では Windows の機能テストを回し、UI 変更は Windows のスクリーンショットでレビューする。Linux CI は開発時の回帰検出に使う。BDD の受入条件とドキュメントのリンク・再現手順を差分と一緒に確認する。自前の再生状態制御と保存モデルでは行カバレッジ85%以上を目標とし、ミューテーションテストで重要な条件分岐を検証する。最新シークと世代切替は Lean の状態モデルで性質を検証し、実装との対応をテストで示す。 [現行プレビュー版の受入条件](acceptance.md)

## 要件レビューで決めること

- **AI に依頼できる編集と実行方式**。初回に対応する編集指示、カット候補の精度の評価方法、処理に使うモデルやローカル・外部サービスの選択を決める。外部サービスを使う場合は送るデータの範囲を決める。
- **最初に評価する PC と素材**。対応する Windows バージョン、想定する CPU・GPU、実況素材の解像度・コーデック・フレームレート、評価に使う収録時間を決める。性能目標はこの条件で合意する。
- **入力・出力範囲**。初回に対応する動画・音声形式と VFR の扱い、MP4 の映像・音声コーデック、字幕の焼き込みが必要かを決める。
- **文字起こしの評価**。日本語の実況用語、複数話者、ゲーム音の混入を含む標本を作り、認識と時刻合わせの合格基準を決める。実行方式とモデルへの依存は評価後に確定する。
- **Windows の配布形態**。ポータブル ZIP とインストーラーのどちらを使うかを決める。
