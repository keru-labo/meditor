# エディターの設計

初回リリースで扱う編集ルールと操作は、[編集ドメイン設計](design/editing-domain.md) と [画面と操作の設計](design/editor-screens.md) に記載する。このページではプレビュー版の構成と実装を扱う。

## Rust と Slint

エディターは Rust、UI は Slint と winit で実装する。採用と切り替えの記録は [ADR 0001](adr/0001-rust-windows-editor.md) と [ADR 0002](adr/0002-rust-editor-cutover.md) にある。

Slint の仮想化した字幕一覧が表示行を取得する。編集欄で字幕を変更すると対象の1行だけを更新する。日本語 IME の変換、確定、候補位置は Windows 実機で確認する。タイムラインはシーク用のトラックと素材区間入力を持つ。動画は共有 RGB バッファから Slint に提示する。D3D11 のネイティブプレビュー領域との統合は今後の検証項目。

AI 編集の接続方式は [ADR 0003](adr/0003-codex-app-server.md) を参照。

## プロジェクト形式

UTF-8 JSON。クリップを持たない version 1 では元動画全体を再生する。version 2 では単一のクリップを `clip` の `source_start_us` と `source_end_us` に保存し、タイムラインの先頭に配置する。終了時刻は区間に含まれない。フレームの途中から始まる区間では、開始位置を含むフレームを表示できる。音声は区間内に時刻を持つサンプルを再生する。

字幕の時刻は整数のマイクロ秒。通常はタイムライン先頭を 0 として保存する。AI が区間を適用して `captions_use_source_time` が有効な場合は素材先頭を 0 とし、プレビューと書き出しではクリップ開始位置を基準に表示時刻を求める。字幕区間は半開区間 `[start_us, end_us)` で、同時発話は重複区間として保存する。字幕 ID は並べ替え・本文更新後も維持する。音声オフセットが正なら動画より遅れて鳴り、負なら音声冒頭の一部を省く。音声素材は初期版で最大32本。読み込み時に相対パスをプロジェクトのディレクトリから解決し、保存は同じファイルシステム内の一時ファイルを置換する。 [AI 区間選択と字幕時刻](features/ai-clip-editing.md#エディターでの試用)

version 1 と 2 の両方で、Undo / Redo の候補を任意の `edit_history` に保存できる。`edit_history` 自体の version は 1。エディターは素材の長さを読み込んだ後、履歴の容量、件数、字幕の ID、素材区間、各操作の再適用順を検査してから復元する。 [履歴の仕様](features/edit-history.md)

```json
{
  "version": 1,
  "video": "recording.mp4",
  "proxy": "proxy.mp4",
  "audio": [
    {"name": "ゲーム音", "path": "game.wav", "offset_us": 0, "gain": 0.3},
    {"name": "話者A", "path": "voice-a.wav", "offset_us": 120000, "gain": 0.7}
  ],
  "captions": [
    {"id": "1", "start_us": 500000, "end_us": 1500000, "speaker": "話者A", "text": "いくよ"}
  ]
}
```

`proxy` は任意。現行版は選んだプロキシの時刻対応が素材準備時に保たれていることを前提とする。次のプロキシ管理では素材ハッシュ、変換パラメーター、PTS 原点、入力と出力の対応を記録する。VFR と編集リスト付き素材の対応は未検証。

## 再生、スクラブ、音声

- 元動画とプロキシに常駐デコーダーを持つ。ワーカー内の要求スロットは最新の要求で上書きする。移動量が大きい場合や逆方向ではキーフレームに戻り、対象時刻までデコードする。古いスクラブの結果はワーカーと GUI の両方で判定し、描画前に破棄する。対象位置を含むフレームを優先し、半開区間の終了以降のフレームは表示しない。
- スクラブを開始すると音声を止め、新しい再生世代を割り当てる。終了時は同じ時刻を元動画で要求し、そのフレームが揃った後で音声を指定位置からプリロールする。再生中は SDL のキューから消費されたサンプル数を論理時計に使う。デバイス出力の物理時計とのずれは計測対象。
- 音声デバイスの初期化と PCM ミックスは専用ワーカーで行う。時刻をサンプル位置に換算し、各トラックのオフセットとゲインを適用して合算し、16 bit に収める。シークで世代を切り替え、古いワーカー結果とキューを破棄する。動画の RGB 変換もワーカーで行う。
- 現行の置換境界は、動画要求・結果を扱う `VideoWorker`、Slint へのフレーム設定、音声の位置と出力を扱う `AudioMixer`。Windows GPU 版ではフレーム型を CPU RGB または参照カウント付き D3D11 サーフェスに広げ、音声サンプルの供給とデバイス出力を分離する。

## Windows の高速経路

FFmpeg の D3D11VA デバイスに描画側の `ID3D11Device` を渡し、`AV_PIX_FMT_D3D11` のフレームからテクスチャ配列とサブリソース番号を取得する。レンダーが完了するまで FFmpeg のフレーム参照を保持する。デコード面を直接サンプリングできないときは D3D11 Video Processor または GPU 内コピーで表示形式へ変換する。GPU 内コピーと CPU 読み戻しは別々に数える。PIX または GPUView で staging texture と CPU Map の有無を検証する。非対応 GPU やコーデックはソフトウェア経路へ戻す。

音声は WASAPI のイベント駆動レンダーに PCM を渡し、`IAudioClock` と QPC を基準に映像の提示時刻を決める。停止・リセット後に新世代の音声だけをプリロールし、ループバックで同期を確認する。

## AI 動画編集、自動文字起こし、書き出し、配布

AI の編集結果を GUI からも扱えるよう、字幕やカットの操作は共通のプロジェクトモデルに反映する。AI 動画編集と自動文字起こしの機能範囲は製品要件に記載する。 [製品要件](requirements.md)

日本語文字起こしの候補は whisper-rs から whisper.cpp を呼ぶ実行経路。モデル、リサンプル、文字またはトークン境界の精度を検証する。トークン時刻をそのまま日本語の単語境界と扱わず、分かち書きと音声アラインメントを別途評価する。初期の話者は入力トラックで区別する。単一音声の話者分離は別の工程。字幕はプロジェクト時刻から字幕ファイルへ変換する。動画の書き出しは UI の外で FFmpeg に編集区間、音声ミックス、字幕を渡して実行する。

Windows x64 の実行ファイルには FFmpeg 共有 DLL と MSVC ランタイムが必要。SDL2 は静的にリンクする。配布では依存ライセンス、FFmpeg のビルド情報、必要なランタイムを記録し、クリーンな Windows 上で起動を確認する。現段階はビルドと評価手順まで。
