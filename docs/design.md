# エディターの設計

## C++ とネイティブ UI

C++20 を選んだ。FFmpeg の C API、Direct3D 11 と WASAPI の COM API、wxWidgets を同じ言語で扱える。Rust には所有権や並行処理の利点がある。これらの API を接続する範囲では FFI とプラットフォーム固有コードが残るため、初期のネイティブ統合は C++ にそろえる。 アプリとメディア処理の実行時依存からは Qt、QML、Qt Multimedia、Python を除外する。

wxWidgets のネイティブ text control で OS の日本語 IME を使う。IME の変換・確定・再変換は Windows 実機で確認する。仮想化した字幕一覧が表示行を取得し、字幕の確定時は対象の1行だけ更新する。動画表示は独立したネイティブの子ウィンドウで、CPU 表示から D3D11 のスワップチェーンへ置き換えられる。現行タイムラインはシーク用スライダー。トラック編集を加える際は、可視時間帯と重なる区間だけを照会するインデックスと、DPI を考慮した描画を導入する。

## プロジェクト形式

UTF-8 JSON の version 1。時刻はプロジェクト先頭をゼロとする符号付き整数のマイクロ秒。字幕区間は半開区間 `[start_us, end_us)` で、同時発話は重複区間として保存する。字幕 ID は並べ替え・本文更新後も維持する。音声オフセットが正なら動画より遅れて鳴り、負なら音声冒頭の一部を省く。音声素材は初期版で最大32本。読み込み時に相対パスをプロジェクトのディレクトリから解決し、保存は同じファイルシステム内の一時ファイルを置換する。

```json
{
  "version": 1,
  "video": "recording.mp4",
  "proxy": "proxy.mp4",
  "audio": [
    {"name": "ゲーム音", "path": "game.wav", "offset_us": 0, "gain": 0.3},
    {"name": "話者A", "path": "voice-a.wav", "offset_us": 120000, "gain": 0.7}
  ],
  "captions": [
    {"id": "1", "start_us": 500000, "end_us": 1500000, "speaker": "話者A", "text": "いくよ"}
  ]
}
```

`proxy` は任意。現行版は選んだプロキシの時刻対応が素材準備時に保たれていることを前提とする。次のプロキシ管理では素材ハッシュ、変換パラメーター、PTS 原点、入力と出力の対応を記録する。VFR と編集リスト付き素材の対応は未検証。

## 再生、スクラブ、音声

- 元動画とプロキシに常駐デコーダーを持つ。ワーカー内の要求スロットは最新の要求で上書きする。移動量が大きい場合や逆方向ではキーフレームに戻り、対象時刻までデコードする。古いスクラブの結果はワーカーと GUI の両方で判定し、描画前に破棄する。
- スクラブを開始すると音声を止め、新しい再生世代を割り当てる。終了時は同じ時刻を元動画で要求し、そのフレームが揃った後で音声を指定位置からプリロールする。再生中は SDL のキューから消費されたサンプル数を論理時計に使う。デバイス出力の物理時計とのずれは計測対象。
- 音声デバイスの初期化と PCM ミックスは専用ワーカーで行う。時刻をサンプル位置に換算し、各トラックのオフセットとゲインを適用して合算し、16 bit に収める。シークで世代を切り替え、古いワーカー結果とキューを破棄する。動画の RGB 変換もワーカーで行う。
- 現行の置換境界は、動画要求・結果を扱う `VideoWorker`、フレームを描くネイティブ `Screen`、音声の位置と出力を扱う `AudioMixer`。Windows GPU 版ではフレーム型を CPU RGB または参照カウント付き D3D11 サーフェスに広げ、音声サンプルの供給とデバイス出力を分離する。

## Windows の高速経路

FFmpeg の D3D11VA デバイスに描画側の `ID3D11Device` を渡し、`AV_PIX_FMT_D3D11` のフレームからテクスチャ配列とサブリソース番号を取得する。レンダーが完了するまで FFmpeg のフレーム参照を保持する。デコード面を直接サンプリングできないときは D3D11 Video Processor または GPU 内コピーで表示形式へ変換する。GPU 内コピーと CPU 読み戻しは別々に数える。PIX または GPUView で staging texture と CPU Map の有無を検証する。非対応 GPU やコーデックはソフトウェア経路へ戻す。

音声は WASAPI のイベント駆動レンダーに PCM を渡し、`IAudioClock` と QPC を基準に映像の提示時刻を決める。停止・リセット後に新世代の音声だけをプリロールし、ループバックで同期を確認する。

## AI 動画編集、自動文字起こし、書き出し、配布

AI の編集結果を GUI からも扱えるよう、字幕やカットの操作は共通のプロジェクトモデルに反映する。AI 動画編集と自動文字起こしの機能範囲は製品要件に記載する。 [製品要件](requirements.md)

日本語文字起こしの候補は whisper.cpp の C++ 実行経路。モデル、リサンプル、文字またはトークン境界の精度を検証する。トークン時刻をそのまま日本語の単語境界と扱わず、分かち書きと音声アラインメントを別途評価する。初期の話者は入力トラックで区別する。単一音声の話者分離は別の工程。字幕はプロジェクト時刻から字幕ファイルへ変換する。動画の書き出しは UI の外で FFmpeg に編集区間、音声ミックス、字幕を渡して実行する。

初期配布の候補は Windows の x64 アプリと vcpkg が配置した DLL をまとめたポータブル ZIP。ビルドに使った vcpkg のコミット、依存ライセンス、FFmpeg のビルド情報、必要なランタイムを記録し、クリーンな Windows 上で起動を確認する。現段階はローカルビルドと評価手順まで。
