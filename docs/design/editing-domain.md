# 編集ドメイン設計

チャットで編集を依頼し、タイムラインを GUI で修正し、履歴から戻して書き出す流れを設計する。対象となる利用者の振る舞いは [初回リリースの機能定義と BDD](../features/README.md) にある。時刻や操作の名称は [編集用語](../ubiquitous-language.md) に従う。

## 編集で扱うもの

| 対象 | 関係と責務 |
| --- | --- |
| プロジェクト | 素材への参照、タイムライン、文字起こし結果、処理ノード、チャット履歴、作業履歴を持つ。編集を適用するごとに新しい編集版を識別できる。 |
| 素材と素材トラック | 収録した動画・音声およびそのトラック。別録り音声は同期の基準とオフセットを持つ。分離音声は元の録音と時刻の対応を保持する。 |
| タイムラインと編集トラック | 映像・音声・字幕の配置と再生順を持つ。タイムライン内の同じ素材を複数箇所に配置できる。 |
| クリップ | 参照する素材トラック、素材区間、編集トラック、配置先を持つ。素材が同じクリップも別々に識別する。 |
| 文字起こし結果と字幕 | 文字起こし結果は発話、話者、単語時刻を素材に対応付ける。字幕はタイムライン上の編集対象で、作成時に使った発話・クリップを追跡できる。人が直した本文や区間を識別できる。 |
| 処理グラフ | 素材・クリップ・編集トラックなどの入出力と、フィルターと設定値を持つノードを接続する。接続によって処理の順序、分岐、合成を表す。 |
| AI の接続設定 | Codex App Server の接続状態を参照する。今後、映像・音声を外部送信する場合は送信先とデータ種別ごとの許可を管理する。 |
| 編集依頼と変更 | 編集依頼には指示、参照した素材や編集状態、実行結果がある。変更は実行者と対象を持ち、AI の場合は元のチャット指示を参照できる。 |
| 書き出し依頼 | 書き出し方法、出力設定、承認状態と、書き出し開始時点の編集・素材参照を持つ。 |

### 時刻と参照の整合性

- 素材区間とタイムライン区間は終了を含まない。クリップの素材区間は参照する素材の範囲内にあり、長さは正とする。タイムラインへの配置は先頭からの非負の時刻を使う。
- 等速のクリップでは、対象の素材時刻からクリップの素材開始時刻を引き、配置時刻を足すとタイムライン時刻になる。素材の 30 秒から始まるクリップをタイムラインの 10 秒に置くと、素材の 33 秒はタイムラインの 13 秒になる。音声は同期オフセットを加味して対応する素材時刻を求める。
- 同じ素材区間を複数のクリップが使う場合、逆引きには対象クリップを含める。再文字起こしは指定された範囲と音声トラックに限定し、参照先の発話と字幕が一致するかを確認する。編集済みの字幕に重なる場合は反映の選択を得る。 [文字起こしの仕様](../features/transcription.md)
- クリップやトラックを変更・削除するときは、それに依存する字幕や接続先を確認する。GUI と AI のどちらの操作でも参照が解決できる状態を保つ。処理グラフは入出力の種類、必要な接続と値、利用する FFmpeg 構成で処理できることを検証し、有効になった構成を編集状態に反映する。 [FFmpeg 設定とノード編集](../features/ffmpeg-controls.md)

## 編集を適用する

GUI の操作とチャットから得た編集案は、同じ編集操作として検証・適用する。操作には対象と設定値を含める。一つの依頼でまとめて反映する変更は、すべて検証できた時点で一つの変更として適用する。たとえばカットと音量を変更する依頼は、音量設定に失敗した段階でカットだけが変更される状態を作らない。

AI の編集依頼を受け付けるときに参照状態を記録する。結果を反映する直前に、依頼が有効であることと、参照した素材・文字起こし・配置先の変更がないことを確認する。中断後や前提が変わった後に届いた結果でプロジェクトを更新しない。中断や前提変更の理由はチャットで確認できる。 [AI 編集の仕様](../features/chat-editing.md)

AI に映像・音声を渡すときは、送信先の接続方式が入力を扱えて、送信時点で設定の許可があることを確認する。必要な条件を満たせない場合は理由を示す。 [AI サービスへの接続・送信許可](../features/ai-connections.md)

### 作業履歴

- 作業履歴は適用された順に並び、変更の対象、実行者、時刻、関係するチャットを参照できる。チャット履歴と編集状態をプロジェクトの保存・再開で復元する。
- GUI とチャットの通常の Undo / Redo は共通の順序で、一つの変更を単位に扱う。Undo の後で別の編集を適用すると、それまでの Redo の候補は空になる。過去の作業は履歴から参照できる。
- 特定の変更を戻す依頼では、対象の変更と、その対象に依存する後続の編集を確認する。たとえば、別クリップへの字幕修正は残せる。作成したクリップに後から付けた字幕に影響が及ぶ場合は、対象と影響を示し、同意が得られた内容を反映する。
- 差し戻しは元の変更と関連付けた新しい変更として記録する。確認中に関係する編集が変わった場合は、影響を再確認する。 [履歴と差し戻しの仕様](../features/edit-history.md)

## 書き出しに使う編集版

| モード | 書き出しを開始する時点 |
| --- | --- |
| そのまま書き出す | AI の編集結果を適用した時点で、その編集版と出力設定を確定する。 |
| 確認してから書き出す | 制作者が確認した編集版と、その依頼の出力設定で承認する。承認操作と版の確定の間に内容が変わった場合は更新後の内容を表示し、確認を取り直す。 |

開始した書き出しは、確定した版のクリップ・字幕・ミックス・処理グラフ・出力設定を使う。その後の GUI 編集は新しい版に反映する。素材の参照を確定できない場合は理由を示し、完了として扱わない。保存先・画質などは今回の依頼で指定した値を優先し、指定がなければ既定値を使う。 [書き出しの仕様](../features/video-export.md)

この設計の初版では、編集操作のグループ化、版の確定、履歴操作を定義する。ノードの具体的な保存形式、履歴の格納方法、再配置・速度変更時に字幕を追従させる詳細は、各機能の設計で決める。 [画面と操作の設計](editor-screens.md) · [現行プレビューの設計](../design.md)
