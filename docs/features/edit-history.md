# チャット履歴と作業履歴

会話はチャット履歴として、AI と人が適用した変更は時系列の作業履歴としてプロジェクトに保存する。作業履歴には誰が何を変更したかを記録し、差し戻しでは対象にした変更も参照できる。保存したプロジェクトを開き直すと、両方の履歴を見返してチャットを続けられる。

GUI とチャットの両方から、同じ作業履歴に対して Undo / Redo できる。一つの依頼でまとめて適用した編集は、一つの変更として扱う。たとえば AI がカットと音量をまとめて変えた場合、Undo で両方が戻り、Redo で両方が再適用される。

チャットから「字幕は残して、前のカット変更だけ戻して」のように指示できる。AI が作業履歴から対象を特定し、独立した後続編集を保持したまま、指定された変更を打ち消す操作を新しい履歴として追加する。対象を特定できない場合は確認する。

差し戻す変更に後から行った編集が依存している場合は、その影響を示してから制作者の確認を得る。たとえば、消えるクリップに付いた字幕の扱いを示す。確認を取り消した場合、タイムラインや字幕は現在の状態を保持する。 [作業履歴のシナリオ](edit-history.feature)

## プレビュー版で使える操作

ツールバーの「元に戻す」「やり直す」は、開いているプロジェクトで変更した字幕本文・話者名とクリップの素材区間に対応する。対象の変更がないときはボタンが無効になる。字幕は入力欄で反映された変更ごと、素材区間は「区間を適用」ごとに記録される。

保存すると、Undo と Redo の候補も現在の編集内容と一緒に保存され、開き直した後に使える。それぞれ新しい順に最大128件・512 KiB の範囲で、連続した候補を保持する。古いプロジェクトの履歴は空で始まる。履歴の字幕 ID や素材区間が現在のプロジェクトと整合しない場合は、編集内容を開いたうえで履歴を初期化し、メッセージを表示する。SRT 読込で字幕一覧を置き換えると履歴は初期化される。 [実装済み操作の受入テスト](../../rust/tests/history_acceptance.rs)

## CI での検証

Rust の受入テストは [履歴のシナリオ](edit-history.feature) を展開し、実装済みのシナリオごとに Rust の編集・保存 API を実行する。未定義のステップや期待結果との不一致は CI を失敗させる。チャット経由の操作など、未実装のシナリオには `@planned` を付けて一覧に出す。予定シナリオの名前と例の件数は受入テストで照合する。

Linux CI では、一時コピーから Redo 候補を消す処理を除き、対応するシナリオが期待した検査で失敗することを確認する。Rust の受入テストでは、字幕編集、区間変更、Undo、Redo、保存と再読込の5種類から作った長さ5の全3,125操作列を、編集状態のスナップショットを使う参照モデルと照合する。

ローカルでも、エディターをビルドできる環境から実行できる。

```sh
cargo test --manifest-path rust/Cargo.toml --locked --test history_bdd -- --nocapture
```

## PR の画面レポート

同じリポジトリ内の PR では、Linux CI が合成プロジェクトを使って Undo / Redo の2シナリオをエディターで実行する。Slint の編集コールバックを呼び、実際のボタンの有効・無効、字幕一覧、素材区間を照合する。各操作後の画面を保存し、値が期待と違う場合もその時点の画面を記録する。

PR の CI と Pages への公開が終わると、PR コメントの「BDDレポートを開く」からブラウザで直接閲覧できる。「シナリオ」を押してメニューを開閉し、一覧から表示するシナリオを切り替えられる。右側に操作の流れを縦に並べ、各ステップで操作手順、直後のスクリーンショット、判定理由、期待値と実際の値を確認できる。失敗したシナリオを先に表示する。同じ PR の URL は維持し、現在のコミットの結果で更新する。

公開は既定ブランチ上のワークフローが行う。GitHub Pages の Source は GitHub Actions を使う。レポートの一覧ページは設けず、各ページに `noindex` を設定する。公開 PR や共有された URL からはログインなしで閲覧できる。 [公開ワークフロー](../../.github/workflows/history-report.yml)
