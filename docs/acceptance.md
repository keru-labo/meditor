# 最初のプレビュー版の受入条件

| Given | When | Then | 検証 |
| --- | --- | --- | --- |
| 日本語字幕10,000件と2本以上の音声がある | JSON を開き、字幕本文を変えて保存する | 全字幕と話者、音声オフセットを保持し、本文だけ更新する | `project` |
| BOM と CRLF を含む UTF-8 SRT がある | SRT を取り込む | 字幕の時刻、改行、本文を読み込む | `project` |
| 元動画を開いている | 同じスクラブ世代で異なる位置を連続要求する | 最新の位置を採用する | `media` |
| 元動画と同じ時刻のプロキシがある | プロキシで移動し、元動画に戻る | 元動画の同じ時刻のフレームを返す | `media` |
| ゲーム音と話者2本を登録した | 途中から再生して別の位置へシークする | 新しい音声キューを作り、その位置から論理時計が進む | `media` |
| 字幕10,000件を表示した | 一覧末尾へ移動し、日本語 IME で変換・確定する | 目的の行だけ編集される | GUI 実機 |
| 元動画を再生している | タイムラインを往復し、別の位置で手を離す | 元動画に戻り、複数音声と一緒に再開する | GUI 実機 |

同じ Windows PC での再現方法は [性能計測](performance.md) を参照。

## PR で Windows の画面を確認する

同じリポジトリのブランチから作成した PR では、CI が **Windows プレビュー** コメントに PNG を直接表示します。再実行すると同じコメントが更新されます。PNG はコメントから表示できるよう、専用の `ci/screenshots/pr-番号` ブランチに保存します。フォークからの PR では画像投稿用の書き込み権限がないため、**Checks → Windows tests and screenshot → Details** から実行を開き、Artifacts の画像を確認できます。

Windows ジョブは MSYS2 UCRT64 のビルド済みライブラリと、SHA-256 で検証した FFmpeg 共有 SDK を使って Release をビルドし、CTest を実行後、合成動画と10,000件の字幕を読み込んだエディターのウィンドウを撮影します。プレビュー領域に合成動画が描画されたことを判定し、画面を保存できなかった場合はジョブを失敗させます。音声テストはダミーデバイスで実行します。

## Rust のシーク制御

以下は [Rust の受入テスト](../rust/tests/seek_acceptance.rs) で確認する。

| 前提 | 操作 | 期待結果 |
| --- | --- | --- |
| プロキシを利用できる | 同じ位置へ続けてシークし、古い要求のフレームが返る | 最新の要求に対応するフレームだけを一度受理する |
| 再生中にプロキシでスクラブしている | 指定位置でスクラブを終える | 元動画のその位置を要求し、元動画の結果を受理した時点で再開できる |
| 一時停止中でプロキシがない | スクラブして終了する | 元動画でシークし、再生の再開を指定しない |
| シークが保留されている | 停止または素材を切り替え、古いフレームが返る | 古いフレームを破棄する |
